# 뚝딱교실·뚝딱 제작실 UX 실사용 검수 — 2026-10-17

## 검수 범위와 방식

- 사용자 여정: **홈 → 만들 자료 선택 → 제작실 → 통합 캔버스 → 글씨 추가 → 요소 속성 수정**.
- 실제 Chromium 자동 검사 화면 크기: **1440×900(PC), 1024×768(노트북), 768×1024(태블릿), 390×844(휴대전화), 320×720(소형 휴대전화)**.
- 확인 요소: 화면 넘침, 실제 편집기 진입, ‘새로 만들기’ 대화상자와 기본 작업 성공, 클릭 가능한 대상 크기, 모바일 도구 탐색, 페이지 문구, 분리된 보관함 안내, CSS 대비.
- 수집 자료: GitHub Actions의 `UX_AUDIT`/`UX_CANVAS`/`UX_EDITOR` 로그, `canvas-visual-review` 아티팩트의 `ux-*.png`. 자동화로 도형을 렌더링하고 진입을 확인했지만, 인간 대상 사용성 테스트·실제 iPhone Safari 테스트를 대신하지는 않는다.
- 기능 회귀는 별도 `studio-mixed-workflows.e2e.cjs`의 교사 도구·그룹·사진·음악·PNG/WebM·저장 복원 테스트에서 검사한다.

## 발견 사항과 우선순위

### P0 — 다음 구조 개편에서 우선 해결

1. **작업 공간이 다단계로 느껴짐.** 홈페이지의 새 자료 진입, ‘제작실 홈’, 통합 캔버스 안의 도구 패널이 서로 다른 페이지 계층으로 표현된다. 동작은 정상이나 현재 위치·돌아갈 위치가 직관적이지 않다. 권고: 작업 진입 후 **캔버스 한 화면을 중심**으로 상단에 '홈 / 자료명 / 저장 상태'만 남기는 단순 경로. 제작실 홈은 내 작업 브라우저로 기능 분리.
2. **서로 다른 저장 위치의 명칭.** ‘내 활동’(타이머·퀴즈·자리표)과 ‘내 작업’(제작물), 고급 편집기 원본은 실제 저장·재열기 방식이 다르다. 단순한 한 개 보관함처럼 오해할 수 있다. 권고: 나중에 ‘보관함’ 단일 입구에 유형 필터를 둔다. 이번 패치에서는 홈에 차이점과 개별 백업 경로를 직접 안내했다.

### P1 — 사용 빈도가 높은 동선의 개선

3. **모바일 도구 메뉴 탐색성.** 통합 캔버스 하단 탐색에 9개 항목이 각각 최소 약 63px여서 390px 화면에 다 보이지 않는다. ‘사진 넣기’, ‘교사 도구’, ‘내보내기’가 수평 스크롤 위치에 따라 숨는다. 현재 상단에 별도 내보내기 버튼은 존재하지만 중복되고 혼란스럽다. 권고: 메뉴를 **추가 / 편집 / 페이지 / 수업 / 저장** 5개로 묶고 하위 탭으로 세분화한다. 이번 패치에서는 우선 표현을 구체화했다.
4. **홈의 동일 도구 반복과 긴 화면.** ‘무엇을 만들까요?’, ‘수업에 바로 쓰는 도구’, ‘기능 바로가기’에서 같은 편집기들이 반복된다. 모바일 홈의 전체 문서는 약 2196px로 확인됐다. 권고: 첫 화면은 '자료 만들기'와 '이어서 작업'을 우선하고, 바로가기 반복 부분은 접거나 개인화한다.
5. **작은 누르기 영역.** 일부 홈 링크와 즐겨찾기 별이 모바일 권장 누르기 영역보다 작았다. 이번 패치에서는 즐겨찾기·홈 섹션 행동·메뉴 버튼 등의 영역을 확대했다.
6. **낯선 단어 및 중복 명칭.** ‘캔바형’, ‘자간’, ‘테두리 비율’ 등의 표현은 초보 교사에게 기능을 예측하기 어렵다. ‘요소’와 ‘업로드’도 무엇을 넣는지 즉시 알 수 없다. 이번 패치에서 ‘글씨’, ‘도형·사진’, ‘사진 넣기’, ‘글자 간격’, ‘사진 틀 비율’ 등의 말로 교정했다.
7. **어두운 글씨 대비 부족.** 최초 CSS에서 10~11px 보조 글씨의 예시 색상 #8993a6는 흰색 배경과 약 **3.09:1**, #8a94a6는 약 **3.06:1**에 그쳤다. 일반 텍스트 기준 4.5:1보다 낮다. 이번 패치에서 주요 설명 글씨를 더 진한 색으로 교체했다(선택한 #5d6677은 흰 배경에서 약 **5.78:1**). 다른 배경색·상호작용 상태에 대해서는 후속 대비 검사 필요.

### P2 — 다듬을 때 개선

8. **반복되는 ‘도구’라는 말.** 홈의 ‘도구 찾기’, 제작실의 ‘제작 도구’, 캔버스의 도형 추가 메뉴가 모두 '도구'라서 영역을 혼동할 수 있다. 사용자 행동과 연결된 글씨 중심 명칭으로 단계별로 구분 권장.
9. **슬라이더의 숫자 피드백.** 투명도(0~1), 사진 확대(1~4), 그림자 흐림(0~25)에 현재 값이 옆에 상시 표시되지 않는다. 권고: 각각 '100%', '2.0배', '흐림 6' 같은 즉시 숫자 피드백 제공.
10. **제작/파일 형식 차이.** 통합 캔버스는 이미지·인쇄·WebM을 내보내고, 편집 가능한 PPTX/DOCX/HWPX는 별도 전문 도구에서 만든다. PDF 파일의 텍스트를 자유 수정할 수 있다고 읽히지 않도록 각 파일 형식을 선택할 때 짧은 설명 필요.
11. **초보 사용자 첫 사용 가이드.** 빈 디자인에 글씨를 추가했을 때 '한 번 선택 / 두 번 글씨 고치기 / 모서리 크기 변경'이 화면에서 자연스럽게 드러나도록 3개 단서만 점진적으로 노출하는 것이 적절하다. 강제 튜토리얼은 권장하지 않는다.

## 이번 검수에서 적용한 변경

- 홈 제작 시작 카드와 새 작업 대화상자의 안내를 자연스러운 한국어 중심으로 정리.
- 홈 '이어서 작업하기'에서 서로 다른 저장 위치를 구분하고 백업 경로를 명확히 설명.
- 캔버스 9개 탭의 행위 명칭을 더 구체적으로 수정. 데이터 속성 `data-design-tab` 및 저장 데이터 포맷은 유지.
- 글씨 간격·사진 틀 비율·확대·테두리 표현 보강.
- ‘도형·사진’ 삽입 패널에서 이미 별도 탭이 있는 템플릿·교사 도구·페이지 관리 버튼의 중복 표시를 숨김(기존 요소 및 동작 API 유지).
- 홈 섹션 링크, 즐겨찾기 버튼 및 사이드바 일부 컨트롤의 누르기 영역 확대. 수정 후 320·390·768px 기준 점검에서 36px 미만 조작 대상 수 0개(측정 대상 기준).
- 흰색 바탕 위 희미한 소형 안내 텍스트의 색 대비 개선.
- PC/노트북/태블릿/모바일/소형 모바일 Chromium 자동 화면 흐름·새 작업 대화상자 검사와 스크린샷 아티팩트를 CI에 추가.

## 남겨둔 범위

- 모바일의 9개 메뉴를 5개로 합치는 것은 제품 수준의 정보 구조 개편이므로 별도 UX 작업으로 추진.
- ‘내 활동’과 ‘내 작업’ 데이터 저장소를 실제로 통합하는 것은 자료 손실 가능성이 있어 이번에 변경하지 않음.
- 실제 iPhone Safari, 키보드만 사용하는 모든 경로, 스크린 리더, 대용량 문서 성능, 통합 출력 픽셀 동등성은 후속 4.0-D 검수에서 수행.
