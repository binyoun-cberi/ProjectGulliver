# 뚝딱교실 공통 화면 기준

## 적용한 기준

- 34개 독립 페이지가 `gulliver-app-shell.js`의 메뉴 한 개를 사용한다. 메뉴 순서는 홈 → 제작실 → 내 보관함 → 수업 준비 → 우리 반이다. 휴대폰에서도 같은 순서로 표시한다.
- 홈의 왼쪽 메뉴는 도구 찾기·즐겨찾기·템플릿 등 홈 내부 탐색만 담당한다. 제작실의 옆 메뉴는 편집 도구만 담당한다. 페이지마다 있던 별도 사이트 메뉴는 제거했다.
- `gulliver-design.css`가 교사용 배경·글자·색·제목·입력폼·버튼·탭을 정의한다. 주 행동은 보라색, 보조 행동은 흰색, 삭제는 붉은 글자와 테두리로 구분한다.
- 제목은 페이지당 한 번을 기본으로 하고, 학급 운영 단계는 제목 아래에 배치한다. 화면에 개발 버전을 표시하지 않는다.
- 별도 창을 여는 행동은 **학생 화면 열기**, 현재 창의 설정을 숨기는 행동은 **이 화면으로 보여주기**, 브라우저 확대는 **전체화면**으로 구분한다. 별도 학생창 버튼은 공통 헤더에 둔다.
- 활동 저장 버튼도 같은 헤더 안에 둔다. 구형 고정 버튼이 메뉴 위에 겹쳐 나타나지 않게 했다.

## 작업 상태와 학생 화면

타이머·낱말카드의 교사용 실행은 `gt-executing`으로 구분한다. 실행 중에도 공통 헤더에서 학생창을 열 수 있다. 학생용 같은 창 보기(`student-view`), 발표(`presentation`), 수업 전체 실행(`running`)에서는 사이트 메뉴를 숨긴다.

제작실과 수업 준비에 들어간 같은 출처의 편집기는 자체 사이트 메뉴를 만들지 않는다. 상위 창이 실제 제작실·수업 준비·교사 도구 호스트인지 확인한다. 학생창과 학생 투표 참여 페이지에는 교사용 디자인과 메뉴를 추가하지 않았다.

교사용 설정·관리 컨트롤에만 공통 스타일을 적용한다. 캔버스 내용, 문서·슬라이드, 퀴즈 선택지, 자리표의 좌석, 게임 화면과 외부 고급 편집기 내부는 작업 결과이므로 공통 버튼 스타일의 대상에서 제외한다.

## 저장과 이동

저장 키와 파일 형식은 유지한다. 제작실과 수업 준비는 공통 메뉴·브랜드 링크를 누를 때 현재 편집 내용을 저장한 다음 이동한다. 동적으로 만들어진 메뉴도 같은 저장 대기를 거치도록 이벤트 위임으로 연결했다.

## 검수

- `node --test tests/*.test.cjs`: 기존 데이터·편집·백업 및 교사 도구 회귀 검사. Chrome이 있으면 두 모니터 연동과 학생 정보 비공개 검사도 실행한다.
- `node --test tests/unified-interface.e2e.cjs`: 주요 화면·교사 도구·영상·음악 28개 페이지를 1536px·390px에서 열어 메뉴 중복·메뉴 폭·본문 가림·학생창 버튼 중복을 확인한다. 명단 저장·재열기, 발표 화면의 메뉴 숨김, 편집기 임베드의 메뉴 생략, 자료 저장 후 다른 화면 이동도 검증한다.
- `node --test tests/ui-v56.e2e.cjs tests/whole-journey-audit.e2e.cjs`: 390·768·1440·1920px 메뉴와 제작 → 저장 → 보관함 → 수업 가져오기 → 실행 → 백업·재열기를 확인한다.
- 스크린샷은 `test-artifacts/unified-interface-*.png`에 생성하며 CI 아티팩트로 확인할 수 있다.
