# 매일 수업 · 문제지 생성 품질 계약 (1차)

## 목표와 적용 범위
문제지 생성기 수정에서 **요구 → 스펙 → 검증 설계 → 구현 → 도전자 검증 → 사람의 리뷰**를 한 PR로 추적한다. 처음에는 문제 생성 코어, 교과 데이터, 문제지 화면·인쇄를 적용 대상으로 삼는다. 교과별 교육과정 해석은 [2022 성취기준 대조 문서](worksheet-2022-alignment.md)를 참고하되, 기록된 미검증 항목을 검증 완료로 오인하지 않는다.

## 역할과 산출물
| 단계 | 제안자 | 도전자 | 조율자 | 완료 산출물 |
| --- | --- | --- | --- | --- |
| 1 스펙 | 코드 조사, 사용자 의도, 가정·제약·완료 기준 | 해결책을 먼저 제시하지 않고 모호성·예외·성취기준 근거를 질문 | 답변을 반영하거나 판단 보류 | PR의 요구/스펙 단락 |
| 2 구현 | 완료 기준에서 테스트를 먼저 도출, 최소 변경 구현 | 독립 테스트·재현 시드·코드/화면 근거로 반박 | 실패 근거로 최대 3회 수정 | 테스트와 변경 코드 |
| 3 전달 | CI 결과·변경 파일·출력 샘플 정리 | 근거가 실제 코드와 일치하는지 재확인 | 승인 요청·수정 요청·상위 보고 | 검증된 PR 설명 |

**사람의 리뷰가 최종 승인이다.** GitHub Actions는 결정적인 검사만 수행하며, 이 단계만으로 여러 LLM 에이전트가 독립 토론했다고 주장하지 않는다. 실제 AI 제안자와 도전자 사용 시 서로의 결론 대신 원문 스펙, 코드 diff, 재현 자료를 독립적으로 읽게 한다.

## 단계별 인수인계 계약
### 1) 스펙 (Spec)
- 사용자가 얻을 결과, 변경 범위와 비범위, 대상 학년·교과·단원·세부 유형을 명시한다.
- 정확한 정답, 한 문제의 채점 기준, 수 범위, 문항 수, 반복 출력의 결정성을 정의한다.
- 성취기준의 **일부 연습**과 **전체 성취기준 달성**을 구별한다.
- 미검증 성취기준 코드는 그대로 공개하지 않고 근거가 확인될 때까지 연결을 보류한다.
- 변경 전 실패 사례와 통과 조건을 구체적으로 적는다.

### 2) 빌드 (Build)
- 새 오류의 재현 시드를 테스트에 먼저 기록한다.
- Node 단위 테스트, 교차 시드 검사, 정답·선택지·중복 검사를 실행한다.
- Chrome에서 학년/단원/유형 선택, 24문항, 정답 숨김/보기, 인쇄용 PDF를 확인한다.
- 교육적 사실성·사료 출처·문장의 자연스러움은 자동화 검사와 별개로 기록한다.

### 3) 전달 (Delivery)
- PR 템플릿의 다섯 단락을 모두 작성한다.
- GitHub Actions 실행 링크, 재현 절차, 화면/PDF 아티팩트, 실패/미검토 항목을 남긴다.
- 조율자가 테스트 통과와 교육적 승인 여부를 각각 기록한다.
- 고위험 실패(오답, 거짓 성취기준, 개인정보 노출)는 통과 처리하지 않는다.

## 검증 게이트
- 변경에 관계된 파일: daily-worksheet-core.js, daily-worksheet.js, daily-worksheet.css, 문제지 만들기.html, data-standards.js, 관련 테스트·문서.
- 자동: 기존 코어 회귀, 다양한 시드의 도전자 검사, PR 스펙 완성도, Chromium 브라우저 기본 동작 및 출력 아티팩트.
- 수동: 출제 목표의 적합성, 국어 문장 품질, 역사 사실·출처, 장애학생 접근성, 실물 프린터 여백/가독성.
- **경고:** 파일 경로나 테스트만 변경된 기존 PR에도 전용 게이트가 실행될 수 있으므로 템플릿을 작성한다.

## 검증 루프·에스컬레이션
1. 제안자가 구현 및 검증 결과 제출
2. 도전자가 구체적인 반례·경로·시드로 문제 제기
3. 조율자가 수정 후 재검증, 또는 판단 보류
4. 기본 2회, 최대 3회 수행; 해결되지 않으면 실패를 공개하고 사람에게 전달한다.

## 시작 명령
- node --test tests/daily-worksheet-core.test.cjs tests/daily-worksheet-challenger.test.cjs
- node --test tests/worksheet-pr-contract.test.cjs
- Chromium E2E는 GitHub Actions의 worksheet-quality-gate.yml이 브라우저 의존성을 설치한 다음 수행

**주의:** 별도 개발자 승인 없이 자동 병합 또는 자동 배포하지 않는다. 전체 CI가 아닌 한 작업에서 실행한 일부 테스트를 전체 검수 완료라고 표기하지 않는다.
