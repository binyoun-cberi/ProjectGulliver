# 통합 캔버스 4.0 — 고급 개체 편집 개발 계획

- 계획 확정: 2026-10-15
- 목표: 교사가 한 화면에서 학습지·포스터·발표·짧은 영상의 글씨/그림을 캔바처럼 손쉽게 다듬는다.
- 프로젝트: `binyoun-cberi/ProjectGulliver`, 실행 화면 `통합 캔버스.html`
- 상태: **기획/작업 분할 완료. 이 문서의 기능은 아직 구현 완료로 간주하지 않는다.**

## 1. 현재 확인한 출발점

- `studio-unified-core.js`: `gulliver.unified.canvas.v1`, 요소 종류 `text/rect/ellipse/triangle/star/line/image`, 페이지 최대 40장·페이지당 개체 최대 150개. `cleanElement`가 허용 필드만 남기므로 새로운 속성의 모델/검증/직렬화를 먼저 수정해야 한다.
- `studio-unified-editor.js`: 선택 식별자 `selected`가 한 개만 가능하고, 이동·크기·앞뒤 순서 변경도 하나의 개체를 기준으로 한다. SVG→PNG·인쇄 출력과 `studio-unified-video.js` 영상 합성은 별도 코드 경로가 있다.
- 3.6: 영상·WAV·자막 다중 트랙, 파형, 음량, 페이드, WebM 내보내기. 3.7: 교사 도구 8종 및 발표 중 도구 호출·복귀.
- 전문가용 PhotoCraft, VectorCraft, DeckCraft, WordCraft, PDFCraft, FilmCraft, SoundCraft는 **별도의 고급 편집기**로 유지. 현재 통합 캔버스가 이들 엔진/프로젝트 포맷을 완전히 대체하지 않는다.

## 2. 4.0 완료의 의미

아래 5개 단계가 모두 구현·검증되고 발표/교사 도구 기능이 회귀하지 않아야 **4.0 완료**로 선언한다. 단계별 PR은 개별 병합하며, 문서만 병합해 완료했다고 알리지 않는다.

### 4.0-A — 모델·선택 기반 (첫 구현 작업)

1. 여러 개체를 선택 가능: Shift+클릭, 선택 상자(마우스/터치), 개별 선택 해제, Esc. 기존 단일 선택과 더블클릭 글씨 편집 유지.
2. 선택된 전체 개체를 함께 이동·복제·삭제, 실행 취소/다시 실행.
3. 그룹 만들기/그룹 해제. 그룹을 이동·크기 변경해도 자식별 위치·크기·글씨·이미지 정보를 잃지 않는다.
4. 데이터 확장: 기존 `format: gulliver.unified.canvas.v1`을 깨지 않고 선택적인 안정적인 `groupId`, `rotation`, `locked`, `hidden` 등의 필드를 점진적으로 추가. 선택 UI 상태는 영구 저장하지 않으며 실제 그룹/회전 속성만 저장.
5. 마이그레이션: 이전 3.0~3.7의 텍스트/도형/이미지/동영상/음악/자막과 교사 도구 생성 페이지에 새 필드가 없어도 동일하게 열리고 저장되도록 한다.

**수용 기준:** 개체 3개를 선택해 그룹→이동·크기 조절→저장→새로 열기→그룹 해제→Undo/Redo를 순서대로 수행해도 위치/내용/그룹 정합성이 유지됨. 잠긴 개체는 조작 불가, 그룹 ID 충돌 및 잘못된 데이터는 거부/정규화.

### 4.0-B — 배치·레이어·회전

1. 자유 회전 핸들 및 각도 직접 입력(예: -180°~180°), Shift 기반 15° 단위 스냅.
2. 여러 개체의 왼쪽/가운데/오른쪽, 위/중간/아래 정렬 및 가로·세로 균등 간격.
3. 캔버스/다른 요소의 중앙·모서리·간격 스냅 가이드, 필요하면 꺼지도록 설정.
4. 순서가 보이는 레이어 목록(표시·숨김·잠금·순서 변경). 그룹은 목록에서 접기/펼치기. 원본 도형의 앞뒤 배치 기능 유지.
5. 드래그 중 터치 스크롤 충돌 방지, 모바일에 충분한 크기의 회전·이동 손잡이.

**수용 기준:** 화면상의 회전 중심·위치·순서가 저장 뒤 같고, 그룹 내부 관계가 보존되며 출력 이미지/PDF·WebM에서 회전·레이어 순서가 동일함.

### 4.0-C — 글씨·사진 고급 편집

1. 텍스트 전체에 글꼴 모음/굵기/기울임/밑줄/줄 간격/자간 및 기본 텍스트 박스 정렬. 한국어/영어 혼합 시 실제 이용 가능한 폰트 폴백을 사용한다.
2. 이미지 자르기(원본 비파괴: cropRect), 화면 비율, 원형/둥근 사각형/기본 도형 마스크. 마스크는 미리보기·인쇄·영상 출력이 일치해야 함.
3. 색상 투명도, 기본 테두리/그림자. 복잡한 PSD 필터·RAW 색보정까지 첫 4.0 범위로 약속하지 않는다.
4. 일부 글자만 다르게 꾸미는 리치 텍스트, 복잡한 벡터 패스/고급 필터는 데이터 호환·출력 엔진 검증 후 후속 확장으로 구분한다.

**수용 기준:** 사진을 원형으로 자르고 글꼴·줄간격을 수정한 뒤 PNG/PDF·영상 프레임에 같은 모습이 표현됨. 기존 PNG/JPG·SVG/학습지 도안·교사 도구 데이터가 변경 없이 열림.

### 4.0-D — 출력 동등성·모바일 품질 확정

1. **동일 개체 렌더러 원칙**: 편집 화면, SVG/PNG, PDF 인쇄, WebM 영상 프레임에서 회전·마스크·폰트·그룹·숨김·투명도가 가능한 한 같은 결과. 경로가 지원하지 않는 기능은 화면에 정확하게 안내하며 조용히 누락하지 않는다.
2. PC Chrome/Edge와 모바일 터치 자동 검사. 실제 iPhone Safari 동작은 자동 Chromium 에뮬레이션 결과와 분리하여 표시.
3. 그룹·대량 선택 후 페이지 전환/복제/삭제/미디어 트랙/발표 실행/교사 도구 실행 후 복귀/ZIP 백업 복원까지 회귀 검사.
4. 40페이지×150요소 한도의 큰 문서에서 무한 리렌더·무한 Undo·터치 이벤트 누락 방지. 성능 예산을 측정하여 과도한 렌더링을 최적화.
5. 접근성: 버튼 라벨, 키보드 사용, 포커스 복귀, 터치 핸들, 축소 화면에서 속성창 겹침 방지.

**수용 기준:** 기존 `.github/workflows/studio-checks.yml`의 integration·browser-e2e·official-media-release 성공과 신규 E2E 모두 통과. GitHub Pages 배포 성공 확인 후 4.0 사용자 공개.

## 3. 구현 원칙

- **한 번에 교체하지 않는다.** 기존 DOM 기반 요소 편집기·`GulliverStudioAdapter`·IndexedDB·ZIP 백업·3.6 멀티트랙·교사 도구를 유지한다.
- **검증 모델 우선**: 불필요한 전체 저장 포맷 변경을 피하고 `cleanElement`, `element`, `validate`, `fromDesign`, `fromSlides`에서 선택적 속성 round-trip 검증을 수행한다.
- **개별/그룹 변형 계산 분리**: 변형 및 스냅 계산을 순수 함수 모듈에 두고, 입력 장치·화면 렌더와 분리해 단위 테스트 가능하게 한다.
- **여러 출력 경로 동시 보정**: `studio-unified-editor.js`의 DOM+SVG, `studio-unified-video.js`의 canvas 합성, 출력 인쇄 CSS, 멀티트랙 영상 합성의 시각 결과를 함께 검증한다.
- **PDF/PPTX/HWPX의 의미 구별**: 통합 캔버스에는 현재 PDF 인쇄 기능이 있지만 편집 가능한 PPTX·DOCX·HWPX 직접 출력이나 기존 PDF 본문 편집은 **4.0의 완료 조건이 아니다**. 별도 고급 편집기 엔진과의 안정적 공유 형식이 검증될 때 후속 단계로 옮긴다.
- **로컬 우선**: 교사·유아의 사진과 이름은 기존처럼 기기 로컬 저장에만 남긴다. 외부 서버·클라우드 동기화는 이번 4.0 범위 밖.

## 4. 우선 시험 시나리오

1. **학급 이름표**: 텍스트+테두리를 그룹화하고 한 장에서 8개 배치 → 균등 정렬 → A4 인쇄 → JSON/ZIP 재열기.
2. **통합활동 발표**: 사진 2장 원형 마스크 → 그룹 회전 → 슬라이드 애니메이션 → 발표 중 타이머 호출 → 종료 후 같은 슬라이드 복귀.
3. **세계 여러 나라 학습지**: 도형·글씨 12개 다중 선택/잠금/그룹 → 폰트 변경 → PNG와 PDF의 배치 비교.
4. **짧은 안내 영상**: 이미지 크롭+자막+WAV 트랙 → WebM 출력 → ffmpeg 프레임 검사와 기존 오디오 합성 회귀 확인.

## 5. 이 버전에서 하지 않을 일

- ArtCraft의 PSD·AI·PPTX·DOCX·FilmCraft 프로젝트 포맷을 완전 호환한다고 주장하지 않는다.
- 전문 영상 색보정/키프레임 곡선, 오디오 MIDI/EQ, 실시간 공동 편집, MP4 인코더, 기존 PDF 본문 편집은 후속 과제로 둔다.
- 그림/문서 전문 편집기를 성급히 삭제하거나 고급 기능을 간편 캔버스로 강제 마이그레이션하지 않는다.

## 6. 작업 관리

- 상위 Epic GitHub Issue와 단계별 하위 Issue를 연결한다.
- 실제 기능 개발은 **4.0-A 모델/다중 선택**부터 시작하고, 각 기능은 PR + CI + 배포 검증 뒤 완료로 표시한다.
- 이 문서는 기술 계약 및 검수 목표를 정한 로드맵이며 코드 구현 결과를 대신하지 않는다.
