# 뚝딱 제작실 2.2 — 제작실 사이의 미디어 전달

## 구현된 동선

| 출발 | 도착 | 실제 전달물 | 방법 |
|---|---|---|---|
| 음악 뚝딱 간편 | 영상 뚝딱 간편 | WAV 배경음악 | 공통 상단 `배경음악 보내기` |
| 발표 뚝딱 | 영상 뚝딱 간편 | 선택한 슬라이드 PNG | 다른 제작실 → 영상 |
| 발표 뚝딱 | 영상 뚝딱 간편 | 슬라이드 전체의 이미지 목록 | `전체 슬라이드 → 영상` (5장 이하) |
| 도안 뚝딱 | 영상 뚝딱 간편 | A4 이미지 | 다른 제작실 → 영상 |
| 도안·발표 | 문서·도안·PDF | 공통 이미지 | 기존 이미지 공유 기능 유지 |
| 그림 뚝딱(PhotoCraft) | 문서·영상 | 사용자가 출력한 JPG/PNG | 공식 편집기에서 이미지 저장 → 공통 전달창에서 선택 |
| SoundCraft 고급 | 영상 뚝딱 간편 | 공식 편집기에서 저장한 WAV | 영상 간편 편집 → WAV 파일 추가 |

## 간편 영상의 배경음악

- WebAudio로 WAV를 먼저 디코딩하고 `MediaStreamAudioDestinationNode` 오디오 트랙을 캔버스 영상 트랙과 합쳐 `MediaRecorder` WebM 출력에 전달합니다.
- 음악 음량(0~1), 반복 여부, 음원 제거를 지원합니다.
- 원본 영상 클립의 소리는 아직 합성되지 않으며 간편 영상은 최대 5장면 / 45초입니다.
- iPhone Safari 등 WebM 캡처가 지원되지 않는 브라우저는 기존과 같이 출력 제한을 알립니다.

## 프로젝트 데이터 안정성

- 음악 원본 Blob은 기존 IndexedDB `media`에 `audio/wav`로 저장합니다.
- 영상 모델의 `audio: {mediaId,mime,name,volume,loop}`가 선택 사항이며, 과거 `audio` 필드가 없는 프로젝트는 정상 복원됩니다.
- 통합 백업 JSON에 영상 클립과 WAV 원본이 포함됩니다. 복원 시 영상 클립과 음원의 미디어 ID를 새 ID로 치환합니다.
- 원본 정리 기능은 다른 영상 작업에서 사용 중인 WAV도 삭제하지 않습니다.
- 파일당 15MiB, 미디어 전체 최대 18개, 백업 JSON 최대 120MiB 제한을 유지합니다.

## 아직 직접 연동하지 않는 부분

- 공식 FilmCraft 프로젝트(`.fcproj`)와 SoundCraft 세션(`.scraftz`)을 상호 변환하거나 통합 자동 저장하지 않습니다.
- PhotoCraft 원본 이미지 프로젝트에서 직접 캔버스 데이터를 추출하지 않습니다. PNG/JPG 출력 후 전달만 지원합니다.
- 발표 슬라이드는 원래 PPTX 애니메이션 파일이 아니라 현재 슬라이드의 정적 PNG 이미지로 전송합니다. 5장보다 많다면 축소하여 전송하며 **자동 삭제하거나 앞의 5장만 몰래 보내지 않습니다**.
- 10~30분 FilmCraft 출력, 마이크/스피커 루프백 및 iPhone/iPad Safari 실기기 검수는 별도 항목입니다.

## 자동 검증

`tests/studio-cross-media.e2e.cjs`에서 Chrome 실제 제작, FFprobe를 통한 WebM 비디오·오디오 트랙 검사, 통합 백업·복원, 슬라이드 일괄 및 그림 파일 전달을 검사합니다. 기존 `studio-checks.yml` 전체 회귀 테스트도 실행합니다.
