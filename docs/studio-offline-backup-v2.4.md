# 뚝딱 제작실 2.4 — 서버 없는 대용량 원본 저장 및 ZIP 백업

## 동작 구조

- **GitHub Pages:** 편집기 코드와 화면을 제공하는 정적 호스팅만 사용합니다. 작업 파일이 GitHub Pages 서버로 업로드되지 않습니다.
- **IndexedDB v4:** 기존 간편 프로젝트/사진/음원/폴더 및 공식 프로젝트의 메타데이터를 유지합니다.
- **OPFS (Origin Private File System):** 약 24MiB 이상인 공식 FilmCraft `.fcproj` / SoundCraft `.scraftz` 원본을 브라우저 내부 파일에 저장하고 IndexedDB에는 원본의 파일 키를 기록합니다. 브라우저가 OPFS를 제공하지 않으면 기존 IndexedDB Blob 보관으로 돌아갑니다.
- **ZIP 백업:** 바이너리 파일을 Base64 문자열로 바꾸지 않는 ZIP STORE(무압축) 방식을 자체 자바스크립트로 구현합니다. 압축률 향상보다 메모리 부담과 데이터 손실 위험을 줄이는 것이 목표입니다. 별도 서버나 백업 서비스, CDN 라이브러리가 필요하지 않습니다.
- **예전 JSON 백업:** 이전의 120MiB JSON 내보내기와 JSON 복원 기능을 삭제하지 않습니다.

## 실제 UI

**내 작업 → ZIP 전체 백업 (권장)** 버튼을 누르면 간편 작업, 사진, 영상, WAV, 공식 FilmCraft/SoundCraft 원본, 폴더, 기존 내 활동을 한 파일로 다운로드합니다. ZIP의 메타데이터는 `manifest.json`이고, 각 파일은 `assets/`, `media/`, `official/` 아래에 바이너리 형태로 저장됩니다.

**백업 복원 (.zip/.json)**에서 ZIP 또는 기존 JSON을 선택할 수 있습니다. ZIP 복원은 각 엔트리의 CRC32를 먼저 확인하고 파일 크기, 파일 형식, 목록 참조를 검증합니다. 잘못된 백업은 기존 작업을 삭제하거나 부분적으로 덮어쓰지 않고 오류를 표시합니다.

**저장 공간** 패널은 브라우저에서 제공하는 추정 사용량·허용량, 공식 원본 및 영상·음원·사진 크기, OPFS 사용 가능 여부와 지속 저장 권한을 보여줍니다. `저장 공간 보호 요청` 버튼은 사용자의 직접 클릭에서만 실행되며 브라우저가 허용 여부를 결정합니다.

## 데이터 안정성

- ZIP은 최대 **512MiB**, 최대 **800개 엔트리**입니다. ZIP64, 암호화 ZIP, 압축된 DEFLATE ZIP은 현재 지원하지 않으며 이 제작실에서 생성한 ZIP STORE만 가져옵니다.
- ZIP의 경로 탐색(`../`), 중복 경로, 파일 크기 불일치, CRC32 불일치, 알 수 없는 추가 파일을 거부합니다. CRC32는 **우발적인 파일 손상 탐지**이며 암호학적 위변조 방지 서명이 아닙니다.
- ZIP 원본은 1MiB 단위로 순차 CRC 검사합니다. 출력 Blob은 기존 파일 Blob을 직접 참조하며 복수의 큰 원본을 한 번에 Base64 변환하지 않습니다.
- 큰 공식 프로젝트 복원은 OPFS에 파일을 먼저 임시 저장한 뒤 IndexedDB에서 메타데이터·폴더·프로젝트·소재 전체를 단일 트랜잭션으로 확정합니다. 트랜잭션 실패 시 임시 파일을 정리합니다. 브라우저 프로세스가 아주 갑자기 종료되는 경우 고아 임시 파일이 남을 가능성은 있으나 기존 프로젝트 데이터는 이 과정에서 삭제하지 않습니다.
- 삭제 및 폴더 이름 변경에서도 공식 프로젝트의 기존 OPFS 파일이 불필요하게 다시 쓰이지 않도록 처리합니다.
- **브라우저 데이터 삭제 시 OPFS 및 IndexedDB도 사라질 수 있습니다.** OPFS는 서버 백업이 아닙니다. ZIP을 기기 파일 앱, 외장 저장소 또는 사용자가 선택한 별도 위치에 꼭 보관해야 합니다.

## 모바일

Chrome의 390×844 터치 화면을 에뮬레이션해 버튼 조작, 대용량 원본 보관, 새로고침 후 읽기, ZIP 내보내기를 검사합니다. 이 결과는 **실제 iPhone/iPad Safari 장치 시험을 대신하지 않습니다.** iOS Safari의 다운로드 동작, 가용 저장 용량 및 긴 영상의 WebM/MP4 렌더링은 별도 실기기 검수가 필요합니다. 지원되지 않는 저장 API에서는 IndexedDB로 대체하고, WebM 출력 지원 여부는 기존 2.2 편집기 안내를 유지합니다.
