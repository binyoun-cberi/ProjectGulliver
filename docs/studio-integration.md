# 뚝딱 제작실 1차 통합판

**진입점:** `뚝딱 제작실.html` (뚝딱교실 홈의 자료·기록 → 뚝딱 제작실)

## 통합 범위

- 다섯 작업 종류를 공통 왼쪽 탐색에서 전환: 그림·PDF·도안·발표·문서.
- 기존 제작 화면은 `iframe`으로 사이트 안에 배치하고, 별도 헤더와 안내 영역만 접어 편집에 집중하도록 합니다. 기존 HTML URL과 원본 도구를 **삭제/이동/병합하지 않습니다**.
- `도안`, `발표`, `문서` 세 가지는 기존 편집기 `GulliverStudioAdapter`에 프로젝트 내보내기·불러오기·이름 변경 기능을 연결합니다.
- 편집 중 1.9초 간격으로 변경 여부를 확인해 `IndexedDB`의 `gulliver-studio-v1` 데이터베이스 `projects` 스토어에 비동기 자동 저장합니다. 새로 만들기·최근 작업 열기·복제·삭제·이름 변경·프로젝트 JSON 백업·옛 JSON 불러오기를 제공합니다.
- **그림과 PDF는 자동 저장이 지원되지 않습니다.** PhotoCraft/PdfCraft 원본 WebAssembly의 내부 상태/열린 파일을 부모 제작실에서 직렬화할 수 없기 때문입니다. 도구 안에서 파일을 직접 내려받도록 안내하고 다른 도구로 이동 시 저장 확인 대화상자를 표시합니다.
- 기존 뚝딱교실의 '내 활동' 데이터베이스는 타이머·퀴즈·자리표용 `localStorage`입니다. 1차 버전의 새 제작실 프로젝트는 별도 `IndexedDB`에 저장됩니다. 홈 페이지의 안내문과 기존 내 활동 저장 구조는 보존합니다.

## 공통 소재함

- JPG/PNG 파일만 받으며 **각 2MB 이하**.
- 업로드는 서버 업로드가 아니라 이 브라우저의 `assets` 스토어에 기기 내 Blob 저장을 뜻합니다.
- 등록한 사진을 내려받거나, 현재 열려 있는 **도안·발표·문서** 편집기의 기존 파일 입력창에 파일로 전달하여 사용할 수 있습니다.
- 도안 뚝딱에는 이 연동을 위해 실제 **JPG/PNG 사진 삽입**을 구현했습니다. 사진은 자체 JSON, SVG, PNG 출력에 포함되고 마우스·터치로 위치를 조절할 수 있습니다. 저장 원본 JSON 제한을 24MB로 늘려 사진이 들어간 도안도 다시 열 수 있습니다.
- 브라우저 정책에 의해 JavaScript 파일 입력 전달이 제한되는 환경은 사진 소재함에서 내려받아 수동으로 삽입하도록 안내합니다.
- 소재함 자체에는 자동 백업이 없으므로 기기 변경 시 사용자 파일을 다시 가져와야 합니다.

## 프로젝트 종류별 지원

| 편집기 | 통합 편집 화면 | 자동 기기 저장 | 파일 내보내기 |
|---|---|---|---|
| 그림 | 있음 (기존 PhotoCraft 실행) | 없음 | 원본 도구의 저장 기능 |
| PDF | 있음 (pdf-lib + PdfCraft) | 없음 | 원본 도구의 PDF 저장 |
| 도안 | 있음 | 있음 | JSON / SVG / PNG / PDF 인쇄 |
| 발표 | 있음 | 있음 | JSON / PPTX / PDF 인쇄 |
| 문서 | 있음 | 있음 | JSON / HWPX / DOCX / PDF 인쇄 |

프린트/PDF, PPTX, HWPX, DOCX 출력 엔진은 이번 통합에서 교체하지 않았습니다. 별도의 출력 형식별 실제 프로그램 호환성 검수가 계속 필요합니다.

## 개인정보와 저장 안정성

- 기기 내부의 IndexedDB에만 저장하므로 학교 또는 개인정보가 포함된 자료를 외부 서버로 전송하지 않습니다.
- 브라우저의 저장 공간과 사용자 설정에 따라 저장 실패나 저장소 삭제가 발생할 수 있습니다. 저장소 부족·브라우저 미지원 시 오류를 표시하고 기존 제작기의 원본 JSON 다운로드를 권장합니다.
- 같은 기기에서 브라우저 프로필을 바꾸면 작업이 보이지 않습니다. '원본 백업' 버튼으로 프로젝트별 JSON을 내려받을 수 있습니다.
- 파일/그림을 포함한 프로젝트는 최대 26MB, 사진 한 장은 최대 2MB로 제한하고 있습니다.
- 기존 페이지에 단독으로 접근할 때는 원본 `beforeunload` 안내와 JSON 저장을 그대로 사용합니다. 통합 제작실 내부에서는 부모가 자동 저장 후 교체하므로 중복 종료 경고를 줄였습니다.
- **자동 저장은 편집기에서 수정한 도안·발표·문서만 대상**이며, PhotoCraft/PdfCraft의 복구는 보장하지 않습니다.

## 1.1 안정화 보강 (2026-10-13)

### 자동 저장의 완료 보장
- 자동 저장이 진행 중일 때 **저장 중…**, IndexedDB transaction 완료 후 **기기에 저장됨**, 실패 시 **저장 실패**를 명시합니다.
- 도구 전환과 제작실 홈 이동은 마지막 편집 내용의 저장을 기다립니다. 저장 실패 시 이동을 막고 편집기를 유지하므로 원본 JSON을 별도로 저장할 수 있습니다.
- 기존 JSON 원본을 가져오면 해당 제작실의 검증 단계를 통과한 직후 초기 내용을 IndexedDB에 곧바로 저장합니다. 추가 수정 없이도 보관함에서 다시 열 수 있습니다.
- 숨김 탭 전환과 페이지 종료 시 저장을 시도하고, 저장 대기/실패나 미반영 변경이 남은 상태로 탭을 닫는 경우에는 브라우저가 허용할 때 경고합니다. 브라우저가 강제 종료될 경우 데이터 영구 보관을 보장하지 않으므로 중요한 원본은 JSON으로 내려받기를 권장합니다.
- 기존 개별 도구의 단독 저장·종료 경고는 유지합니다.

### 사진 소재함 호환성
- 공통 소재함에서 도안·발표·문서로 사진을 전달할 때 파일 입력창을 강제로 채우는 경로보다 편집기의 검증된 `insertImage` 어댑터를 우선 사용합니다.
- 용량 제한과 MIME 형식, 이미지 총량을 각 편집기에서 재검증합니다. JPEG/PNG 2,000,000바이트 이하.
- 폴더 전환 또는 도구 전환 뒤에도 소재함 이미지는 IndexedDB에서 다시 불러옵니다.

### 자동 검수
- 기존 Node 회귀 테스트 외에 Google Chrome 기반 실제 브라우저 통합 검사를 추가했습니다.
- 테스트 범위: 도안 저장→새로고침→복원, 사진 소재함→도안 삽입→복원, 발표·문서 저장, 이전 JSON 파일 첫 열기 후 저장, JSON 백업 다운로드, 저장 오류 발생 시 편집기 이탈 방지.
- GitHub Actions `studio-checks.yml`의 `browser-e2e` 작업으로 실행됩니다.
- 한컴오피스/PowerPoint 실제 프로그램에서의 파일 출력 검수, iPhone Safari 실기기 테스트는 Chrome 자동 검수와 별도로 남아 있습니다.

## 1.2 편집 화면 통합 (2026-10-13)

### 적용된 화면 구조
- **좌측 얇은 작업 유형 메뉴:** 그림·PDF·도안·발표·문서 간 전환.
- **좌측 제작 팔레트:** 템플릿, 요소 삽입, 페이지/슬라이드 목록. 선택 즉시 실제 원래 편집기의 버튼을 실행합니다.
- **중앙:** 기존 도안 SVG·발표 슬라이드·문서 A4 캔버스를 그대로 활용합니다. 부모 iframe에서는 기존 편집기의 중복 헤더·좌우 패널·상단 툴바만 숨겨 공통 제작 화면에 맞춥니다.
- **공통 상단 내보내기:** SVG·PNG·PPTX·DOCX·HWPX·PDF·발표 등 실제 원래 편집기의 동작을 호출하므로 저장 포맷/변환 엔진을 별도로 구현하지 않습니다.
- **우측 속성 편집기:** 실제 편집기의 제목·글씨·색상·위치·크기·슬라이드 내용·메모를 보여주고, 같은 문서 입력 요소에 변경 이벤트를 전달합니다. 기존 문서/표 본문의 직접 편집은 중앙 캔버스에서 계속 가능합니다.
- **우측 탭:** 속성 / 내 작업 / 소재함. 기존 IndexedDB 데이터 구조와 자동 저장을 그대로 유지합니다.
- **태블릿/휴대폰:** 작은 화면에서는 팔레트·속성 패널을 사이드 드로어로 열고 닫습니다. 바깥 영역 클릭과 Esc로 닫을 수 있습니다.

### 호환성 및 후속 작업
- 기존 그림 뚝딱(PhotoCraft), PDF 뚝딱(PdfCraft)은 자체 고급 UI를 그대로 사용합니다. 공통 팔레트·개체 속성창으로 완전히 대체한 것은 **아닙니다**. 통합 전환과 내 작업·소재함은 기존대로 연결됩니다.
- 기존 개별 도구 URL로 들어오면 이전 편집 UI가 그대로 제공됩니다. `?studio=1`로 삽입된 통합 제작실에서만 중복 패널을 숨깁니다.
- 한 번에 하나의 편집 iframe만 사용하고, 이동 시 IndexedDB 자동 저장이 완료돼야 다음 도구로 전환합니다.
- 원본 프로그램의 복잡한 속성/전환효과 등은 '새 창에서 열기' 또는 고급 편집기 원래 화면을 이용할 수 있습니다.
- 문서 내보내기는 Word/HWPX 파일에 대한 실제 한컴/Word 서식 검수를 계속 필요로 하며, iOS Safari 실기기는 Chrome 자동 검사와 별개입니다.
- 구조를 통째로 새 캔버스로 교체하지 않고 기존 편집기 컨트롤을 **프록시**하므로 기존 저장 포맷 및 기능을 쉽게 회귀 검증할 수 있습니다.

### 1.2 자동 검수
- Node 정적/데이터 모델 테스트는 공통 팔레트, 툴바, 속성창의 ID/연결을 포함합니다.
- Chromium E2E 테스트에서는 팔레트로 도안 글씨 추가→속성 수정→저장/복원, 사진 소재함 삽입, 발표 템플릿 및 페이지 이동, 문서 요소 삽입, JSON 원본 백업·불러오기, 저장 실패 시 이탈 방지, 모바일 사이드 드로어 조작을 검사합니다.
