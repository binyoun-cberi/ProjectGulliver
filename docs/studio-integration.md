# 뚝딱 제작실 1차 통합판

**진입점:** `뚝딱 제작실.html` (뚝딱교실 홈의 자료·기록 → 뚝딱 제작실)

## 통합 범위

- 다섯 작업 종류를 공통 왼쪽 탐색에서 전환: 그림·PDF·도안·발표·문서.
- 기존 제작 화면은 `iframe`으로 사이트 안에 배치하고, 별도 헤더와 안내 영역만 접어 편집에 집중하도록 합니다. 기존 HTML URL과 원본 도구를 **삭제/이동/병합하지 않습니다**.
- `도안`, `발표`, `문서` 세 가지는 기존 편집기 `GulliverStudioAdapter`에 프로젝트 내보내기·불러오기·이름 변경 기능을 연결합니다.
- 편집 중 1.9초 간격으로 변경 여부를 확인해 `IndexedDB`의 `gulliver-studio-v1` 데이터베이스 `projects` 스토어에 비동기 자동 저장합니다. 새로 만들기·최근 작업 열기·복제·삭제·이름 변경·프로젝트 JSON 백업·옛 JSON 불러오기를 제공합니다.
- **그림과 PDF는 자동 저장이 지원되지 않습니다.** PhotoCraft/PdfCraft 원본 WebAssembly의 내부 상태/열린 파일을 부모 제작실에서 직렬화할 수 없기 때문입니다. 도구 안에서 파일을 직접 내려받도록 안내하고 다른 도구로 이동 시 저장 확인 대화상자를 표시합니다.
- 기존 뚝딱교실의 '내 활동' 데이터베이스는 타이머·퀴즈·자리표용 `localStorage`입니다. 1차 버전의 새 제작실 프로젝트는 별도 `IndexedDB`에 저장됩니다. 홈 페이지의 안내문과 기존 내 활동 저장 구조는 보존합니다.

## 공통 소재함

- JPG/PNG 파일만 받으며 **각 2MB 이하**.
- 업로드는 서버 업로드가 아니라 이 브라우저의 `assets` 스토어에 기기 내 Blob 저장을 뜻합니다.
- 등록한 사진을 내려받거나, 현재 열려 있는 **도안·발표·문서** 편집기의 기존 파일 입력창에 파일로 전달하여 사용할 수 있습니다.
- 도안 뚝딱에는 이 연동을 위해 실제 **JPG/PNG 사진 삽입**을 구현했습니다. 사진은 자체 JSON, SVG, PNG 출력에 포함되고 마우스·터치로 위치를 조절할 수 있습니다. 저장 원본 JSON 제한을 24MB로 늘려 사진이 들어간 도안도 다시 열 수 있습니다.
- 브라우저 정책에 의해 JavaScript 파일 입력 전달이 제한되는 환경은 사진 소재함에서 내려받아 수동으로 삽입하도록 안내합니다.
- 소재함 자체에는 자동 백업이 없으므로 기기 변경 시 사용자 파일을 다시 가져와야 합니다.

## 프로젝트 종류별 지원

| 편집기 | 통합 편집 화면 | 자동 기기 저장 | 파일 내보내기 |
|---|---|---|---|
| 그림 | 있음 (기존 PhotoCraft 실행) | 없음 | 원본 도구의 저장 기능 |
| PDF | 있음 (pdf-lib + PdfCraft) | 없음 | 원본 도구의 PDF 저장 |
| 도안 | 있음 | 있음 | JSON / SVG / PNG / PDF 인쇄 |
| 발표 | 있음 | 있음 | JSON / PPTX / PDF 인쇄 |
| 문서 | 있음 | 있음 | JSON / HWPX / DOCX / PDF 인쇄 |

프린트/PDF, PPTX, HWPX, DOCX 출력 엔진은 이번 통합에서 교체하지 않았습니다. 별도의 출력 형식별 실제 프로그램 호환성 검수가 계속 필요합니다.

## 개인정보와 저장 안정성

- 기기 내부의 IndexedDB에만 저장하므로 학교 또는 개인정보가 포함된 자료를 외부 서버로 전송하지 않습니다.
- 브라우저의 저장 공간과 사용자 설정에 따라 저장 실패나 저장소 삭제가 발생할 수 있습니다. 저장소 부족·브라우저 미지원 시 오류를 표시하고 기존 제작기의 원본 JSON 다운로드를 권장합니다.
- 같은 기기에서 브라우저 프로필을 바꾸면 작업이 보이지 않습니다. '원본 백업' 버튼으로 프로젝트별 JSON을 내려받을 수 있습니다.
- 파일/그림을 포함한 프로젝트는 최대 26MB, 사진 한 장은 최대 2MB로 제한하고 있습니다.
- 기존 페이지에 단독으로 접근할 때는 원본 `beforeunload` 안내와 JSON 저장을 그대로 사용합니다. 통합 제작실 내부에서는 부모가 자동 저장 후 교체하므로 중복 종료 경고를 줄였습니다.
- **자동 저장은 편집기에서 수정한 도안·발표·문서만 대상**이며, PhotoCraft/PdfCraft의 복구는 보장하지 않습니다.

- `.github/workflows/studio-checks.yml`에서 PR·main 변경 때 문법 및 전체 Node 테스트 실행.

**남은 직접 브라우저 검수:** PC/태블릿/아이폰에서 도안·발표·문서 자동 저장 후 새로고침·다시 열기, 사진 소재함 삽입, PPTX/DOCX/HWPX 열기, 파일 내려받기, PhotoCraft/PdfCraft 내부 WASM 실행, 저용량 저장소 대응.

## 1.1 안정화 보강 (2026-10-13)

### 자동 저장의 완료 보장
- 자동 저장이 진행 중일 때 **저장 중…**, IndexedDB transaction 완료 후 **기기에 저장됨**, 실패 시 **저장 실패**를 명시합니다.
- 도구 전환과 제작실 홈 이동은 마지막 편집 내용의 저장을 기다립니다. 저장 실패 시 이동을 막고 편집기를 유지하므로 원본 JSON을 별도로 저장할 수 있습니다.
- 기존 JSON 원본을 가져오면 해당 제작실의 검증 단계를 통과한 직후 초기 내용을 IndexedDB에 곧바로 저장합니다. 추가 수정 없이도 보관함에서 다시 열 수 있습니다.
- 숨김 탭 전환과 페이지 종료 시 저장을 시도하고, 저장 대기/실패나 미반영 변경이 남은 상태로 탭을 닫는 경우에는 브라우저가 허용할 때 경고합니다. 브라우저가 강제 종료될 경우 데이터 영구 보관을 보장하지 않으므로 중요한 원본은 JSON으로 내려받기를 권장합니다.
- 기존 개별 도구의 단독 저장·종료 경고는 유지합니다.

### 사진 소재함 호환성
- 공통 소재함에서 도안·발표·문서로 사진을 전달할 때 파일 입력창을 강제로 채우는 경로보다 편집기의 검증된 `insertImage` 어댑터를 우선 사용합니다.
- 용량 제한과 MIME 형식, 이미지 총량을 각 편집기에서 재검증합니다. JPEG/PNG 2,000,000바이트 이하.
- 폴더 전환 또는 도구 전환 뒤에도 소재함 이미지는 IndexedDB에서 다시 불러옵니다.

### 자동 검수
- 기존 Node 회귀 테스트 외에 Google Chrome 기반 실제 브라우저 통합 검사를 추가했습니다.
- 테스트 범위: 도안 저장→새로고침→복원, 사진 소재함→도안 삽입→복원, 발표·문서 저장, 이전 JSON 파일 첫 열기 후 저장, JSON 백업 다운로드, 저장 오류 발생 시 편집기 이탈 방지.
- GitHub Actions `studio-checks.yml`의 `browser-e2e` 작업으로 실행됩니다.
- 한컴오피스/PowerPoint 실제 프로그램에서의 파일 출력 검수, iPhone Safari 실기기 테스트는 Chrome 자동 검수와 별도로 남아 있습니다.

## 1.2 편집 화면 통합 (2026-10-13)

### 적용된 화면 구조
- **좌측 얇은 작업 유형 메뉴:** 그림·PDF·도안·발표·문서 간 전환.
- **좌측 제작 팔레트:** 템플릿, 요소 삽입, 페이지/슬라이드 목록. 선택 즉시 실제 원래 편집기의 버튼을 실행합니다.
- **중앙:** 기존 도안 SVG·발표 슬라이드·문서 A4 캔버스를 그대로 활용합니다. 부모 iframe에서는 기존 편집기의 중복 헤더·좌우 패널·상단 툴바만 숨겨 공통 제작 화면에 맞춥니다.
- **공통 상단 내보내기:** SVG·PNG·PPTX·DOCX·HWPX·PDF·발표 등 실제 원래 편집기의 동작을 호출하므로 저장 포맷/변환 엔진을 별도로 구현하지 않습니다.
- **우측 속성 편집기:** 실제 편집기의 제목·글씨·색상·위치·크기·슬라이드 내용·메모를 보여주고, 같은 문서 입력 요소에 변경 이벤트를 전달합니다. 기존 문서/표 본문의 직접 편집은 중앙 캔버스에서 계속 가능합니다.
- **우측 탭:** 속성 / 내 작업 / 소재함. 기존 IndexedDB 데이터 구조와 자동 저장을 그대로 유지합니다.
- **태블릿/휴대폰:** 작은 화면에서는 팔레트·속성 패널을 사이드 드로어로 열고 닫습니다. 바깥 영역 클릭과 Esc로 닫을 수 있습니다.

### 호환성 및 후속 작업
- 기존 그림 뚝딱(PhotoCraft), PDF 뚝딱(PdfCraft)은 자체 고급 UI를 그대로 사용합니다. 공통 팔레트·개체 속성창으로 완전히 대체한 것은 **아닙니다**. 통합 전환과 내 작업·소재함은 기존대로 연결됩니다.
- 기존 개별 도구 URL로 들어오면 이전 편집 UI가 그대로 제공됩니다. `?studio=1`로 삽입된 통합 제작실에서만 중복 패널을 숨깁니다.
- 한 번에 하나의 편집 iframe만 사용하고, 이동 시 IndexedDB 자동 저장이 완료돼야 다음 도구로 전환합니다.
- 원본 프로그램의 복잡한 속성/전환효과 등은 '새 창에서 열기' 또는 고급 편집기 원래 화면을 이용할 수 있습니다.
- 문서 내보내기는 Word/HWPX 파일에 대한 실제 한컴/Word 서식 검수를 계속 필요로 하며, iOS Safari 실기기는 Chrome 자동 검사와 별개입니다.
- 구조를 통째로 새 캔버스로 교체하지 않고 기존 편집기 컨트롤을 **프록시**하므로 기존 저장 포맷 및 기능을 쉽게 회귀 검증할 수 있습니다.

### 1.2 자동 검수
- Node 정적/데이터 모델 테스트는 공통 팔레트, 툴바, 속성창의 ID/연결을 포함합니다.
- Chromium E2E 테스트에서는 팔레트로 도안 글씨 추가→속성 수정→저장/복원, 사진 소재함 삽입, 발표 템플릿 및 페이지 이동, 문서 요소 삽입, JSON 원본 백업·불러오기, 저장 실패 시 이탈 방지, 모바일 사이드 드로어 조작을 검사합니다.

## 1.3 제작물 간 이미지·PDF 전달 (2026-10-13)

### 바로 전달할 수 있는 작업

| 보내는 곳 | 받는 곳 | 동작 |
|---|---|---|
| 도안 뚝딱 | 발표 뚝딱 | A4 도안을 이미지로 만들고 선택한 새 발표에 삽입 |
| 도안 뚝딱 | 문서 뚝딱 | 도안 이미지를 새 문서의 사진 블록에 삽입 |
| 도안 뚝딱 | PDF 뚝딱 | 도안 이미지를 A4 크기의 **실제 PDF 한 장**으로 만들고 PDF 파일 목록에 추가 |
| 발표 뚝딱 | 도안 뚝딱 | 현재 슬라이드를 이미지로 추출해 새 도안에 삽입 |
| 발표 뚝딱 | 문서 뚝딱 | 현재 슬라이드 이미지를 문서에 삽입 |
| 발표 뚝딱 | PDF 뚝딱 | 현재 슬라이드 이미지를 가로 방향 PDF 한 장으로 만들어 파일 목록에 추가 |
| 문서 뚝딱 | PDF 뚝딱 | 문서에서 **인쇄 → PDF로 저장** 후, 저장한 PDF를 ‘저장한 PDF를 편집기로 보내기’에서 선택. 브라우저의 인쇄 파일을 자동 획득하지 않음 |

### 동작과 안전장치

- 도안·발표에서 '현재 화면을 소재함에 보관' 또는 받는 제작실을 고른 후 '이미지 보내기'를 누릅니다.
- 이미지를 내보내기 전에 현재 **원본 도안·발표 작업을 먼저 IndexedDB에 저장**합니다. 저장 실패 시 이동하지 않습니다.
- 출력한 PNG/JPEG는 공통 `assets` 소재함에 별도로 저장됩니다. 대상 편집기에서 자동 삽입에 실패해도 공유한 이미지가 남아 있어 다시 삽입할 수 있습니다.
- 이미지 전달은 새 대상 프로젝트를 열기 때문에 기존 문서·발표·도안을 덮어쓰지 않습니다.
- 문서·발표·도안으로 보낼 때는 원본 편집기의 기존 `insertImage` 검증 함수를 사용하며, 삽입 뒤 IndexedDB에 대상 프로젝트를 저장합니다.
- PDF로 보낼 때는 자체 호스팅된 pdf-lib으로 PNG/JPEG를 실제 PDF로 만들어 `PDF 뚝딱`의 일반 파일 처리 목록에 넣습니다. PDF 결과물은 기존 방식대로 사용자가 내려받아야 하며 PDF 내부 상태의 자동 저장은 아직 지원하지 않습니다.
- 편집기/소재함의 이미지 단일 파일 크기는 2,000,000바이트 이하입니다. PNG가 제한을 넘으면 브라우저 내부에서 JPEG로 압축·축소하며, 지원할 수 없을 정도로 크면 오류를 표시합니다.
- 파일 업로드 서버·외부 변환 서비스는 사용하지 않습니다. 학생 사진·문서 내용이 브라우저를 벗어나지 않습니다. 기기/브라우저를 바꾸면 자동 동기화되지 않습니다.
- 발표 슬라이드 이미지 변환은 교사용 **공유 미리보기** 형태로 제목·본문·사진·배경색을 담습니다. CSS/전환효과/모든 텍스트 레이아웃을 픽셀 단위로 완벽히 복제하는 기능은 아닙니다.
- 문서 → PDF는 브라우저의 기본 인쇄 저장을 이용해야 글씨·표·페이지 분할을 최대한 유지할 수 있습니다. 사용자가 저장한 PDF를 다시 선택해야 하므로 **완전 자동 전달이라고 안내하면 안 됩니다.**
- '그림 뚝딱'(PhotoCraft) WebAssembly 편집 내용을 다른 작업실로 자동 추출하는 것은 아직 지원되지 않습니다.

### 회귀 검수

- `tests/studio-transfer.test.cjs`: 지원 대상, 이미지 용량, 안전한 파일 이름, 실제 도안·슬라이드·PDF API 연결을 검사합니다.
- `tests/studio-transfer.e2e.cjs`: 실제 Chrome에서 도안→문서, 슬라이드→도안, 슬라이드→PDF를 생성/추출하고 기존 원본과 소재함 보존 여부를 검사합니다. 문서 PDF 파일을 사용자가 선택하는 전달 경로도 검증합니다.
- 기존 `tests/studio-browser.e2e.cjs`의 저장·복원·오류 시 이탈 방지 테스트를 유지합니다.
- iPhone Safari 및 실제 한컴오피스·PowerPoint로 파일을 열어 확인하는 수동 검수는 별도입니다.

## 1.4 내 작업 보관·검색·통합 백업 (2026-10-13)

**기기 내 자료가 최우선:** 기존 프로젝트와 사진을 지우거나 별도 서버에 옮기지 않고 `gulliver-studio-v1` IndexedDB 스키마를 v1→v2로 업그레이드합니다. 새 `folders` 저장소가 추가되며 기존 `projects`/`assets` 저장소는 유지됩니다.

- 폴더 추가, 프로젝트별 폴더 이동, 폴더 삭제(프로젝트는 미분류로 이동)
- 작업 이름 검색, 제작 유형(도안·발표·문서), 폴더(미분류 포함), 최근 수정·오래된 순·이름순 정렬
- 기존 **타이머·낱말카드·퀴즈·자리표**의 저장 데이터도 제작실 오른쪽의 '기존 내 활동' 목록에서 열기 가능. 원본 저장 구조는 이전 `classroom-workspace.js`의 `localStorage`를 그대로 유지하며 새로운 형식으로 강제 이관하지 않습니다.
- '전체 백업 저장' → `뚝딱제작실-전체백업-날짜.json` 생성: 도안·발표·문서 프로젝트, 폴더, 이미지 소재함(PNG/JPG base64), 기존 내 활동(폴더 포함).
- '백업 복원' → 위 파일을 선택하고 건수 확인 후 기존 항목을 **덮어쓰지 않고 사본으로 추가**. 기존 폴더명과 같으면 병합하고 프로젝트 ID/이미지 ID는 충돌하지 않도록 새로 만듭니다.
- 프로젝트·폴더·사진은 하나의 IndexedDB 트랜잭션으로 복원하므로 저장 실패 시 부분 복원하지 않습니다. 이후 기존 내 활동은 별도의 `localStorage`에 추가되며 공간 부족 등으로 실패할 때는 오류를 안내합니다. 다른 저장소에 걸친 완전한 트랜잭션은 브라우저에서 보장할 수 없습니다.
- 백업 파일은 로그인 없는 브라우저의 장치에서 만들어지고 다운로드됩니다. 개인정보를 포함할 수 있고 **암호화되어 있지 않으므로** 안전한 장소에 보관해야 합니다. 기기를 바꾸거나 캐시/사이트 데이터를 삭제하면 기존 브라우저에 저장된 작업은 없어질 수 있으니 정기적인 백업을 권장합니다.
- 상한: 프로젝트 500개, 소재함 이미지 150개, 폴더 100개, 통합 백업 JSON 120MB, 프로젝트 한 건 26MB, 소재 이미지 한 건 2,000,000B. 큰 자료는 개별 프로젝트 JSON/원본 파일을 병행해서 백업하세요.
- ZIP/HWP/DOCX 원본을 프로젝트에 자동 편입하는 기능은 포함하지 않습니다. PhotoCraft/PdfCraft 고급 편집기의 **편집 세션**도 아직 백업할 수 없습니다.

### 검수 기준
- 기존 IndexedDB 프로젝트·사진이 스키마 업그레이드 뒤에도 남음
- 폴더 지정 뒤 편집/재저장하고 다시 열어도 분류가 유지됨
- 검색·폴더·정렬 결과가 정확하고 폴더 삭제 시 프로젝트 자체는 유지됨
- Chromium에서 실제 통합 JSON 다운로드 → 완전히 다른 브라우저 프로필에서 복원 → 같은 백업을 두 번 복원해도 덮어쓰기 없음
- 손상된 백업/지원하지 않는 버전은 오류를 안내하고 기존 데이터에 영향 없음
- 기존 전체 회귀 검사와 사진 전달·PDF 편집, 모바일 양쪽 패널 검사를 계속 통과

## 2.0 기반: 영상 뚝딱·음악 뚝딱 추가 (2026-10-13)

통합 제작실은 이제 **그림·PDF·도안·발표·문서·영상·음악**의 일곱 종류를 지원합니다.

### 영상 뚝딱: 짧은 교실 기록 영상

- JPG·PNG 사진과 MP4·WebM 영상을 장면으로 추가하고 순서 변경, 클립 시작 시각/길이, 자막, 가로/정사각형 비율 설정.
- 최대 5장면, 총 45초, 원본 파일 1개당 15MiB, 기기에 저장할 수 있는 미디어 항목 최대 18개.
- 브라우저의 `canvas.captureStream` + `MediaRecorder` 사용. 지원하는 Chrome에서 **WebM 영상 파일**로 출력. 외부 인코딩 서버나 WASM 다운로드 없음.
- **현재 출력 영상은 무음입니다.** 원본 동영상에 녹음된 소리나 배경음악은 아직 영상에 합쳐지지 않습니다. 전환효과, 여러 트랙, MP4 인코딩도 후속 단계입니다.
- Chrome/WebM 지원 브라우저 외에는 내보내기가 제한될 수 있으며, iPhone Safari는 실제 기기 검수가 필요합니다.
- 원본 미디어 파일 자체는 별도 `media` IndexedDB에 Blob 형태로 보관하고, 프로젝트 JSON은 미디어 ID와 편집 설정만 담습니다. 개별 `gulliver.json`으로 원본 미디어가 복원될 수 없으므로 **통합 백업**을 사용해야 합니다.

### 음악 뚝딱: 16칸 리듬·멜로디 제작

- 16칸 음표/박자 제작판, 멜로디·베이스·손뼉·심벌즈 트랙, 음높이·BPM·반복 길이 설정.
- 환영 인사·신나는 놀이·조용한 정리 음악 예시 제공.
- 브라우저 자체 합성으로 PCM WAV를 생성해 미리 듣기·다운로드. 업로드 서버, 외부 사운드 라이브러리, 저작권 불명확한 샘플을 사용하지 않습니다.
- 오디오 파형 녹음·보컬·마이크 녹음·MP3 출력, 정교한 악기 샘플/MIDI 다중 트랙은 아직 지원하지 않습니다.
- 음악 프로젝트는 `music` 유형으로 기존 IndexedDB 프로젝트 자동 저장·폴더·검색·복원에 포함됩니다.

### 보관함 및 이전 버전 호환성

- 기존 `gulliver-studio-v1` 데이터베이스 이름은 유지하면서 스키마 v2→v3 업그레이드: `projects`/`assets`/`folders`는 보존하고 `media` 스토어만 추가.
- 통합 백업 `format=gulliver.studio.bundle`, `version=1`도 유지. 새로운 백업에는 선택적 `media` 배열을 더해 영상 프로젝트의 원본 파일과 ID 대응관계를 저장합니다. 기존 1.4 백업의 `media` 미포함 형식도 가져올 수 있습니다.
- 복원할 때 영상 프로젝트 안의 미디어 ID도 재생성된 ID로 변경하고, 프로젝트·사진·폴더·미디어를 같은 IndexedDB 트랜잭션으로 추가합니다.
- 기존 제작 도구·원본 ArtCraft 라이선스·교실 활동의 localStorage는 변경하지 않았습니다.
- 전체 백업 JSON은 암호화되지 않았으므로 아이들 사진·영상이 포함됐으면 공유/유출되지 않게 안전한 위치에 보관하세요. 현재 전체 백업 한도 120MiB를 넘는 경우에는 영상 원본을 따로 보관해야 합니다.

### 검수

- Node 회귀: 7개 진입점, 영상 스키마, 음악 음표 제한, 실제 WAV RIFF 출력, 미디어 저장/복원 코드 연결.
- Chrome E2E: 음악 생성·WAV 다운로드, 영상 이미지 클립·WebM 출력, 자동 저장, 통합 백업 파일의 미디어 포함, 새 브라우저 프로필에서 ID 재매핑과 재생 자료 복원.
- 남은 후속 단계: 음악을 영상 배경음으로 삽입, 원본 동영상 오디오 합치기, MP4 출력 확장, iPhone Safari/태블릿 실기기 검수.
